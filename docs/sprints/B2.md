# B2 — Cobros parciales e historial en Ventas

Fecha: 2026-09-13. Estado: implementación local; pendiente de aplicar la migración y validar en Supabase antes de cerrar el sprint. B3 no iniciado.

## Alcance

- Nueva venta permite importe inicial cero, parcial o total. La venta y el primer abono se guardan en una sola transacción.
- El detalle muestra abonado, pendiente e historial individual y permite registrar abonos posteriores. Ejemplo: 100 con 40 + 40 + 20 deja saldos de 60, 20 y 0.
- Cada solicitud conserva su UUID al reintentar. La base bloquea la unidad y recalcula el saldo antes de aceptar un abono. Rechaza importes nulos, no positivos, con más de dos decimales o mayores que la deuda; un reintento con datos distintos se rechaza.
- Para saldar una venta se confirma el retiro, salvo que ya esté entregada. La confirmación puede acompañar un pago parcial. Se adelantó este control mínimo de B4 para no introducir pago total sin retiro; los nombres definitivos de estados siguen pendientes en B4.
- Se retiró el interruptor de pago verificado: no permite borrar o revertir cobros. La cancelación corresponde a B5.
- Corregido un espacio residual entre las pestañas de Ventas que creaba un panel vacío y ocultaba la tabla.

Se mantiene el modelo actual sin cuentas; autenticación y RLS para usuarios pertenecen a B12.
